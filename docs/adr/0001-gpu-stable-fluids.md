# Use GPU Compute for the Stable Fluids Simulation

**Status:** Accepted

To deliver an interactive Windows-first 2D Stable Fluids simulation without transferring full fields through the CPU each frame, use raylib 6.2 with desktop OpenGL 4.3 and GLSL 4.30 compute shaders. Represent a 1024 x 1024 cell-centered active grid with a one-cell ghost border in separate float32 shader-storage buffers for velocity, dye, pressure, and divergence; keep fields GPU-resident, use ping-pong buffers for passes that read and write the same field, and use explicit memory barriers between dependent dispatches. Apply the Stam velocity sequence (source, diffuse, project, advect, project), then advect dye with zero dye diffusivity, using closed-box free-slip velocity and no-flux scalar boundaries; advance at a fixed 1/60-second step with 32 Jacobi iterations and viscosity 0.0001. Left-button dragging injects velocity, right-button dragging deposits dye, and a GPU colorization pass presents the scalar dye. Verify solver behavior through the actual production compute shaders on a deterministic small grid; this integration test also verifies compute capability, so a separate smoke executable and CPU solver reference are not maintained.

The accepted performance target is the complete rendered 1024 x 1024 solver at 60 FPS or more on an NVIDIA RTX A2000. With 32 iterations, viscosity 0.0001, brush radius 8, velocity-source gain 0.45, and dye-source amount 2.0, repeated 10-second rendered benchmarks measured 77.622 and 77.673 FPS; a later verification measured 77.136 FPS on an RTX A2000 Laptop GPU with NVIDIA driver 596.52. Only full-rendered results on the target adapter count as acceptance evidence; the retired compute-workload proxy did not model the complete solver or rendering.

This deliberately favors GPU-resident compute over a CPU solver or a graphics-pipeline solver. The initial support target is Windows/OpenGL 4.3; requesting the high-performance adapter does not guarantee it is selected, and results from another adapter must not be reported as meeting the RTX target. 3D fluids, obstacles, physical validation, and guaranteed non-Windows support are out of scope.

The numerical basis is Stam's [Real-Time Fluid Dynamics for Games](https://www.dgp.toronto.edu/people/stam/reality/Research/pdf/GDC03.pdf). The selected compute path uses raylib's [6.2 compute-shader example](https://github.com/raysan5/raylib/blob/6.2/examples/shaders/shaders_rlgl_compute.c) and explicit OpenGL [memory barriers](https://registry.khronos.org/OpenGL-Refpages/gl4/html/glMemoryBarrier.xhtml). The architecture and validation decisions were confirmed in [issue #5](https://github.com/prevosta/raylib-stam/issues/5), [issue #7](https://github.com/prevosta/raylib-stam/issues/7), and [issue #11](https://github.com/prevosta/raylib-stam/issues/11).
